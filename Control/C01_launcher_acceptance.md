## C01-1 连接用例

## C01-2 候选提交及反馈用例

- [ ] 候选来源为当前TaskRun的有效HTTP/附件/MCP操作，受保护提取且不暴露到普通日志；不伪造Execution。
- [ ] 同题单Flag错误：受控平台明确false，原TaskRun保持，下一次Inner输入看到安全反馈并继续；无需人工重建题目。
- [ ] 多Flag第一次正确但未全题：准确记部分进度，不ACHIEVED、不伪装rejected/unknown；后续继续原TaskRun。
- [ ] 平台确认全部正确：才提交整题可信成功；仅LLM声称完成不得结束。
- [ ] 重复候选/duplicate不再计一次正确，不无界重复提交；未知POST不自动重发。
- [ ] 请求已发出/响应已收到/回执已保存/控制提交后重载等中断点可恢复，最多一次真实副作用。
- [ ] 鉴权、技术、平台结束、错次耗尽分开，不能统一回传“flag错误”。

## C01-3 自动赛程/暂停/延时用例

- [ ] 两平台自动串行，每次只有一道本地活动题，Arena reused不会新建重复TaskRun。
- [ ] Benchmark按前端队列；完成题清理仅属于本赛程的远端资源；提示/放弃默认不调用。
- [ ] 立即暂停先关闭新领取/模型/工具/提交准入；在途操作保留已知结果或明确未知，不以kill/cancel替代。
- [ ] 继续仍为同一TaskRun/逻辑会话与有效证据，先核验平台/未知操作，再允许新执行。
- [ ] 本题结束后停止覆盖成功/平台失败/到期，不再领取新题；可以撤销；与立即暂停互不混淆。
- [ ] 单题和整体延时分别生效，幂等不重复加时；整体延时不暗增当前题；不得超越平台截止或复活终态。
- [ ] 延时与deadline/最终提交并发，按可信事务时钟裁决；暂停不冻结平台时钟。
- [ ] Arena本地超时且仍active暂停赛程等待用户处理，不重复next或擅自扣分放弃。
